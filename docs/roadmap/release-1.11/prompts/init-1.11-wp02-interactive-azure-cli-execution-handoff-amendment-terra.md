# INIT-1.11 WP02 — Interactive `sabsf` Azure CLI Execution Handoff Amendment

## Model authority
- **GPT-5.6 Luna** — contract, policy, architecture, governance, reconciliation, acceptance criteria.
- **GPT-5.6 Terra** — PRIMARY: orchestration, exact-command generation, evidence evaluation, approved Azure execution, validation, cleanup, mutation accounting, lifecycle completion.
- **GPT-5.6 Sol** — supporting analysis only; never silently replaces Luna/Terra.

**Selected execution model: GPT-5.6 Terra.**

## Purpose
Narrowly amend the existing WP02 Execution Authority because valid Azure authentication exists only in the interactive Windows `sabsf` Azure CLI profile and is unavailable to the Codex sandbox.

This amendment authorizes the interactive **`sabsf` PowerShell session to execute Azure CLI commands explicitly generated by Terra** for WP02.

It does not broaden WP02 scope, cost limits, architecture, resource types, or acceptance criteria.

## Established evidence
Interactive `sabsf` Azure authentication is valid:
- subscription: `Learn Azure subscription`;
- state: `Enabled`;
- default: `True`;
- `az login`, `az account list`, and `az account show` returned exit code `0`.

Do not require another login unless the interactive profile later proves unauthenticated/expired.

## Binding execution model
**Terra/Codex = orchestrator, command author, evidence evaluator, acceptance authority.**

**Interactive `sabsf` PowerShell = execution transport for authorized Azure CLI commands.**

The previously approved Docker/WSL rule remains unchanged:

**`sabsf` PowerShell executes Docker/WSL commands.**

Required marker:
`AZURE F1 WP02 — INTERACTIVE AZURE CLI EXECUTION HANDOFF: AUTHORIZED`

## Mandatory Azure handoff protocol
For every Azure CLI handoff Terra MUST:
1. state the exact purpose and WP02 gate/probe;
2. provide a copy/paste-ready PowerShell block;
3. resolve known values and generate safe unique names when needed;
4. classify commands as READ-ONLY, CREATE, UPDATE, RESTART/REDEPLOY, or DELETE;
5. identify expected Azure mutations before execution;
6. capture labeled exit codes;
7. request only sanitized stdout/stderr/evidence;
8. never ask the user to paste tokens, passwords, registry secrets, publish profiles, connection strings, or credential payloads;
9. STOP and wait for returned evidence;
10. independently evaluate the evidence;
11. request only missing evidence when incomplete;
12. never infer success because commands were supplied or reportedly executed;
13. include all user-executed Azure mutations in the final mutation audit.

## Scope authorized for manual Azure CLI execution
Only operations required by the existing WP02 authority are authorized:

### Read-only preflight
- account/subscription verification;
- provider/resource/SKU/location discovery;
- region/F1 availability checks;
- relevant App Service/container configuration inspection;
- resource inventory;
- deployment/status/log/config reads required for probe evidence.

### Approved zero-cost mutations
Only the minimum WP02 resource footprint permitted by the published WP01 plan and existing WP02 authority:
- resource group creation if required;
- Linux App Service plan using the verified Free/F1 SKU;
- Web App/custom-container configuration;
- `WEBSITES_ENABLE_APP_SERVICE_STORAGE=true`;
- image reference/configuration required for the probe;
- controlled App Service restart;
- controlled container/image redeployment required by the eight probes;
- deletion/cleanup of WP02-created Azure resources.

No mutation may occur before the strict-zero-cost pre-mutation gate passes.

## Strict `$0.00` boundary
Recurring infrastructure cost must remain:

`$0.00`

Forbidden:
- paid App Service SKU;
- Azure Files;
- Azure Container Apps;
- mandatory ACR;
- paid registry/service;
- paid scaling;
- unrelated Azure resources.

If the required probe cannot proceed without a known recurring charge, STOP. Do not substitute a paid resource.

## Authentication/security boundary
- use only the existing interactive `sabsf` Azure CLI profile;
- do not export/copy Azure CLI profile files into Codex;
- do not transfer auth caches/tokens;
- do not create service principals merely to bypass sandbox isolation;
- do not print tokens;
- sanitize subscription/account output where secrets could appear;
- subscription name may be reported; identifiers should be minimized unless needed for evidence.

## Command-batch discipline
Prefer small evidence-bearing command batches aligned to one gate/probe.

For each command or logical batch use labeled exit codes, e.g.:

```powershell
az <command>
$ec = $LASTEXITCODE
Write-Host "AZ_<LABEL>_EXIT_CODE=$ec"
```

For mutations, Terra must state the expected mutation count before the user runs the commands.

After each material Azure mutation, request read-back evidence sufficient to verify actual resulting state.

## First resumed step
Resume the blocked WP02 authority at the Azure preflight.

Terra must first provide a READ-ONLY `sabsf` PowerShell block that verifies:
- active account/subscription remains `Learn Azure subscription`;
- subscription remains Enabled/default;
- relevant resource providers/status;
- candidate regions;
- App Service Linux Free/F1 availability or equivalent authoritative SKU evidence needed for selection;
- no resource creation.

Terra must STOP for returned evidence.

Only after evaluating this evidence may Terra emit the existing:
`AZURE F1 WP02 — STRICT-ZERO-COST PRE-MUTATION GATE: PASS`

## Subsequent execution
After the pre-mutation gate, Terra may hand off approved Azure mutations required by the existing WP02 authority, one governed batch at a time.

The existing eight empirical probes remain mandatory:
1. F1 availability
2. custom Docker
3. public HTTPS
4. persistent `/home`
5. App Service restart persistence
6. container recycle persistence
7. image redeployment persistence
8. resource inventory

Docker/WSL build/tag/push operations continue to use the existing `sabsf` Docker handoff. Azure CLI operations use this amendment.

## Resource disposition
Default is cleanup.

Retention for WP03 is allowed only when the published WP01 plan permits it, it is useful for WP03, and recurring infrastructure cost remains exactly `$0.00`.

Terra must generate exact cleanup commands, STOP for execution evidence, then verify deletion/retention via read-only inventory.

## Mutation accounting
User-executed Azure CLI mutations are real mutations.

Final audit must separately count:
- Azure resources created;
- Azure resources updated/configured;
- restart/redeploy operations;
- Azure resources deleted;
- Azure resources retained;
- Docker images/containers/registry mutations;
- local temporary files;
- repository/Git/GitHub/Project/milestone mutations;
- Twelve Data requests;
- tags/releases.

Do not report Azure mutation zero merely because execution occurred in interactive PowerShell.

- evidence is insufficient;
- a required command exceeds existing WP02 scope;
