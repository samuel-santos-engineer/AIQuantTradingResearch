No grace, rotation endpoint, clock/expiry witness or persistence. Future operational replacement is coordinated settings update/restart, allowing a planned interruption: old instance stopped, new key configured, new instance accepts only new key. Actual Azure settings or keys are never changed/read by tests. Prod/staging service keys must differ; key never enters browser, URL, logs or image layers.

One synchronous standard HTTPS client, default configurable timeout4s. TLS chain/hostname validation, no redirects/proxies/plaintext fallback;4096-byte response cap and exact fixture JSON validation. Standard blocking DNS (and compound standard-library connect/TLS work) can exceed the nominal elapsed budget before control returns: no hard end-to-end or native DNS cancellation guarantee. No DNS workers, helper processes, custom transport or watchdog supervisor. Configuration/CA loading occurs before refresh. Exhausted budget never publishes a new snapshot; timeout/error preserves prior complete fixture state and marks disconnected.

Owned local delay knobs AIQ_FIXTURE_STATUS_DELAY_MS0..1000 and AIQ_FIXTURE_DELAY_STAGE=headers/body exist only for offline fixture tests, not HTTP control endpoints or production settings. Local short-lived self-signed certificate is generated by existing C# helper; UI mounts only public trust. Never deploy dummy keys/certificates.
